# API Security Testing Automation Framework

This project provides a maintainable Playwright + TypeScript framework for API functional and security testing. It follows API client and Page Object-inspired object modeling, uses environment-driven configuration, and produces HTML/JSON test reports.

## 1. Project overview

The framework supports:
- API functional testing
- Security testing for authentication, authorization, request validation, response validation, headers, CORS, versioning, and rate limits
- Positive and negative testing
- Safe testing against staging/test APIs only
- Reusable API clients and helpers

## 2. Prerequisites

- Node.js 18+
- npm
- Access to a test or staging API environment

## 3. Installation

```bash
npm install
npx playwright install
```

## 4. Environment setup

Copy `.env.example` to `.env` and update values:

```bash
cp .env.example .env
```

Required variables:
- BASE_URL
- API_VERSION
- TEST_USERNAME
- TEST_PASSWORD
- AUTH_ENDPOINT
- USERS_ENDPOINT
- REQUEST_TIMEOUT
- RESPONSE_TIMEOUT
- RATE_LIMIT_REQUESTS

## 5. How to run tests

Run all tests:
```bash
npm test
```

Run security tests:
```bash
npm run test:security
```

Run functional tests:
```bash
npm run test:functional
```

Headed mode:
```bash
npm run test:headed
```

Debug:
```bash
npm run test:debug
```

Show report:
```bash
npm run report
```

## 6. Security test categories

- Authentication validation
- Authorization/BOLA testing
- Request and payload validation
- Response validation and sensitive data detection
- Security headers validation
- CORS and OPTIONS validation
- Rate limiting and timeout validation
- API versioning and method validation

## 7. Test architecture

The project is organized into reusable API clients and helpers:
- `api/clients` contains API abstractions
- `api/helpers` contains security and response utilities
- `config` contains environment and test configuration
- `data` holds JSON fixtures
- `tests/security` contains security-spec coverage

## 8. Authentication setup

Authentication is handled using the `AuthApi` client. Tokens are stored in-memory and reused by other API clients without printing secrets into logs.

## 9. Adding new APIs

1. Create a dedicated API client under `api/clients`.
2. Extend the base class for HTTP methods.
3. Keep endpoint logic centralized and environment-driven.
4. Add helper logic for response and payload validation.

## 10. Adding new security tests

1. Add a new spec under `tests/security`.
2. Use a clear test ID and descriptive title.
3. Validate both positive and negative pathways.
4. Avoid high-volume or destructive probes.
5. Prefer documented behavior or safe, low-risk checks.

## 11. Reports

Reports generated by Playwright include:
- HTML report in `playwright-report`
- JSON report in `reports/results.json`
- Failure screenshots and traces retained when applicable

## 12. CI/CD integration

Example GitHub Actions snippet:

```yaml
- run: npm install
- run: npx playwright install --with-deps
- run: npx playwright test --reporter=html,json
```

## 13. Security testing safety guidelines

- Only test against non-production or authorized staging environments.
- Do not run aggressive rate-limit or brute-force tests.
- Do not spoof trusted proxy headers unless explicitly required.
- Avoid destructive or data-mutating commands outside controlled fixtures.
- Keep payload sizes bounded and test only documented thresholds.

## 14. Troubleshooting

- If the API rejects requests, ensure `BASE_URL` and endpoints are correct.
- If auth fails, check credentials and token extraction logic.
- If Playwright cannot run browsers, run `npx playwright install`.
- If TypeScript errors appear, run `npx tsc --noEmit`.

---

This framework is intended for safe, documented API security verification in test and staging environments.
